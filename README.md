# TSUN Монітор

Простий Android-застосунок для накопичувача **TSUN TSOL-MAU5000** (EMS AECC/SXD) у домашній мережі.
Показує, чи є світло, скільки заряду в батареї і на скільки його вистачить, і надсилає сповіщення,
коли мережа зникає або повертається.

Застосунок працює напряму з інвертором через Wi-Fi (протокол EMS, TCP-порт 8080). Хмара, обліковий
запис і інтернет не потрібні: телефон лише має бути в тій самій Wi-Fi мережі, що й інвертор.

## Що вміє

**Стан**
- заряд батареї і межа заряду;
- чи є мережа (є / немає / невідомо);
- потужність з мережі, вихід інвертора з розбивкою «розетка 2 (Off-Grid)» і «розетка 1 + втрати»;
- температура інвертора;
- скільки лишилося до повного заряду (коли є мережа) або до розряду (коли мережі немає);
- оновлення раз на хвилину, поки застосунок відкритий, і свайпом униз.

**Налаштування**
- максимальна потужність заряду від мережі (0–2500 Вт);
- до якого рівня заряджати батарею (максимальний SOC);
- ємність батареї для розрахунку часу;
- фоновий моніторинг і закріплене сповіщення зі станом.

**Сповіщення** (коли увімкнено фоновий моніторинг)
- мережу відключено / відновлено;
- заряд батареї впав до 20 % і до 10 %;
- статус із зарядом і станом мережі: коли мережі немає або батарея не заряджена до максимуму,
  або завжди — якщо увімкнено «Завжди показувати статус».

Перевірка у фоні відбувається раз на 5 хвилин і лише тоді, коли телефон підключений до Wi-Fi.
Без Wi-Fi статус ховається.

**Кілька інверторів.** Інвертори знаходяться в мережі автоматично (mDNS і перебір адрес своєї
підмережі), або їх можна додати за IP-адресою. Фоновий моніторинг перевіряє всі збережені.

**Детально** (прихована вкладка: три швидкі натискання на «Налаштування») — усі дані інвертора,
регістри керування з можливістю зміни та мінімальний SOC. Для налагодження; змінювати регістри
варто лише тоді, коли розумієте, що вони означають.

## Встановлення

1. Завантажте APK:
   - з вкладки [Actions](https://github.com/meklis/tsun-simple-monitoring/actions) → останній
     успішний запуск **Build APK** → артефакт `tsun-monitor-apk-…` (потрібен вхід у GitHub;
     усередині архіву — `release/tsun-monitor-<версія>-release.apk`);
   - або візьміть готовий файл у того, хто збирав застосунок.
2. Відкрийте APK на телефоні. Android попросить дозволити встановлення з цього джерела
   (браузера чи файлового менеджера) — дозвольте.
3. Оновлення ставляться поверх попередньої версії так само, дані зберігаються.

Потрібен Android 8.0 або новіший.

## Перший запуск

1. Підключіть телефон до тієї ж Wi-Fi мережі, що й інвертор.
2. Відкрийте застосунок: інвертор з'явиться в розділі «Знайдені в мережі». Натисніть на нього.
   Якщо його не видно, введіть IP-адресу інвертора вручну (її видно в налаштуваннях роутера).
3. Відкриється екран «Стан». Наступного разу застосунок одразу відкриє останній інвертор;
   список — кнопка праворуч угорі.
4. Щоб отримувати сповіщення: «Налаштування» → увімкніть **Фоновий моніторинг** і дозвольте
   сповіщення. Натисніть **Зняти обмеження батареї**, якщо застосунок це пропонує.

### Якщо інвертор не знаходиться

- Телефон і інвертор мають бути в одній мережі. На деяких роутерах увімкнена ізоляція клієнтів
  Wi-Fi (AP/client isolation) — тоді пристрої не бачать один одного.
- Інвертор обслуговує лише одне підключення за раз. Якщо його саме опитує інший застосунок
  (TSUN Smart, Home Assistant), запит може не вдатися з першого разу — застосунок повторює його.

### Якщо фонові сповіщення не приходять

Під «Фоновий моніторинг» показано час і результат останньої фонової перевірки. Якщо він давно не
оновлювався, систему обмежує енергозбереження:
- дозвольте роботу у фоні без обмежень («Зняти обмеження батареї»);
- на Samsung: Налаштування → Обслуговування пристрою → Батарея → Обмеження фонового використання —
  приберіть «TSUN Монітор» зі сплячих застосунків.

## Налаштування в застосунку TSUN

_Буде доповнено: які параметри потрібно встановити в рідному застосунку TSUN, щоб накопичувач
працював як резервне живлення._

## Збірка

Потрібні JDK 17+ і Android SDK (`ANDROID_HOME` або `local.properties`).

```sh
./gradlew testDebugUnitTest assembleDebug assembleRelease
```

APK з'являються в `app/build/outputs/apk/{debug,release}/`.

Release-збірка підписується ключем `keystore/release.jks`, описаним у
`keystore/keystore.properties` (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`).
Каталог `keystore/` не зберігається в git. Збережіть ключ: оновлення встановлюються поверх
попередньої версії лише з тим самим підписом. Без ключа release-збірка підписується
локальним debug-ключем.

### CI

`.github/workflows/build.yml` на кожен push, pull request і тег `v*` запускає тести, збирає debug-
і release-APK та публікує їх як артефакт `tsun-monitor-apk-<номер>`. `versionCode` = 100 + номер запуску.

Щоб CI підписував release справжнім ключем, додайте секрети репозиторію
(Settings → Secrets and variables → Actions):

| Секрет | Значення |
|---|---|
| `KEYSTORE_BASE64` | результат `base64 -w0 keystore/release.jks` |
| `KEYSTORE_PASSWORD` | пароль сховища ключів |
| `KEY_ALIAS` | псевдонім ключа |
| `KEY_PASSWORD` | пароль ключа |

Без секретів release-APK підписується тимчасовим ключем і не встановиться поверх збірок,
підписаних справжнім.
